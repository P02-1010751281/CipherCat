# Iteration 001：质量门禁与证据链落地

## Understanding

上一轮全项目审计留下三类 P2 后续：缺少正式单元测试、标准目录证据未机器化、生产构建存在大 chunk；同时循环依赖和 CI 尚未接入。用户已同意按最小增量完成这些改进，并保持 CipherCat 前端试运行与 `metacrypt_server` 后端可信测评的职责边界。

## Implementation approach

遵循 ponytail：复用既有 harness、纯函数和 Vite 路由动态导入，仅新增 Vitest、madge、标准 manifest 校验器、首屏 bundle budget 和 CI 配置；不重写 37 份标准 README，不引入 DSL/AST 或新的运行时框架。

## Changes

- 新增 `tests/unit/` 与 `vitest.config.ts`，以 10 个测试覆盖 Markdown 元数据、工作区迁移、错误处理和类型兼容边界。
- 新增 `docs/standards/standards-manifest.json` 与 `scripts/check-standard-metadata.mjs`，登记 37 个标准目录、33 个本地 PDF SHA-256、来源和 Errata URL。
- 新增 `scripts/check-bundle-budget.mjs` 与 `build:check-bundle`，将 Vite `index-*.js` 首屏入口预算固定为 64 KiB。
- 将编辑器专属 Blockly 块/生成器注册移到编辑器路由，并把 Blockly、文档渲染和 Mermaid 依赖拆成独立动态 chunk。
- 新增 `cycles:check` 和 `.github/workflows/quality.yml`，把单测、类型、lint、标准、循环依赖、文档、构建、bundle、模板/Demo 和生产依赖审计接入质量门禁。
- 同步 README、RULES、开发指南、覆盖说明、审计报告和研究报告；保留可信后端测评边界及“工程回归不等于认证”的表述。

## Problems and resolutions

- 首次 `madge` 安装遇到 TypeScript 6 peer 范围冲突，固定到 `madge@7` 并以 `.npmrc` 保持可重复安装，不降级项目 TypeScript。
- 首次 `verify:all` 因验证 harness 使用的 `jsdom` 未声明而失败，已补为开发依赖并重新完成全量回归。
- bundle 检查脚本首次 lint 暴露 Node `process` 全局未声明，已改为显式导入 `cwd` 并重跑通过。
