# 密码能力地图

本页按用途梳理平台中的密码算法与可复用构件，并说明如何从 Blockly 积木走到用户侧验证和平台随机性测评。它是导航总览；具体积木接口、演示断言和标准原文分别以链接文档为准。

分类按主要用途组织。后量子密码（PQC）不是与“对称密码、散列、公钥”并列的算法用途：ML-KEM、ML-DSA 和 SLH-DSA 分别放在密钥封装或数字签名下，再标明其格基或散列基构造。量子密钥分发（QKD）不属于本平台的范围。

## 1. 如何理解能力状态

| 能力状态 | 能说明什么 | 不能据此推出什么 |
|---|---|---|
| Blockly 积木 | 工具箱中有对应积木；相关语言生成能力见[积木索引](../blocks/INDEX.md)和[标准覆盖矩阵](../standards/COVERAGE.md) | 不自动表示完整算法、所有参数或所有语言实现均已覆盖 |
| 演示与测试 | [演示目录](../../demos/README.md)列出工作区及登记的向量、性质断言或交叉验证 | 某个演示通过，只能说明其登记测试通过；不等于完整标准符合性或认证 |
| 标准参照 | [标准覆盖矩阵](../standards/COVERAGE.md)连接标准条目、原文、公式、伪代码、积木和演示 | 有标准文档不等于对应实现已完成或已验证 |
| 后端随机性测评 | 服务端隔离执行用户提交的 Python 生成器，由服务端流程生成待测样本、执行统计检测并生成报告 | 统计结果不证明熵源质量，也不等于密码模块认证 |

这四类信息相互补充，不应互相替代。

## 3. 各类能力与适用边界

### 3.1 对称密码

对称密码包括分组密码、工作模式、认证加密和序列密码。AES、SM4 是分组密码；ECB、CBC、CTR、XTS 是模式；CCM、GCM、ASCON 提供认证加密；ZUC 与 EEA3 属于序列加密。它们解决的问题不同，不能把模式或认证加密构造当作新的分组密码。

AES 演示包含单轮原语链，不能据此声称演示了完整 AES-128 加密接口。ZUC、GCM、CCM、XTS 和 ASCON 的具体演示及测试范围见[演示目录](../../demos/README.md)与[覆盖矩阵](../standards/COVERAGE.md)。

Metacrypto 后端另有 DES 已知明文密钥区间搜索演示；它是密码分析教学功能，不是 DES 加密积木或生产加密方案。[NIST 已认定 DES 强度不足以保护政府信息](https://csrc.nist.gov/news/2004/proposed-withdrawal-of-fips-for-the-des-and-reques)，DES 不应用于新的生产数据保护。

### 3.2 公钥密码：按用途比较经典与后量子方案

| 用途 | 经典构造 | 后量子构造 | 当前演示范围提示 |
|---|---|---|---|
| 密钥建立 | ECDH、X25519、SM2 密钥交换 | ML-KEM（格基密钥封装机制） | 密钥协商与 ML-KEM 密钥封装采用不同协议接口；ML-KEM 演示覆盖登记的参数与流程，不代表所有参数集 |
| 数字签名 | RSA、ECDSA、EdDSA、SM2、SM9 | ML-DSA（格基）、SLH-DSA（散列基） | RSA 和 ML-DSA 有登记测试；SLH-DSA 演示覆盖若干结构和性质，不代表完整参数族或完整 KAT |
| 公钥加密 | RSA、SM2 | McEliece/Goppa（仅教学构件） | RSA 演示采用教学用 PKCS#1 v1.5 流程；McEliece/Goppa 仅演示数学与译码步骤，不代表完整密码系统 |

后量子是面向量子攻击模型的安全目标分类；“格基、散列基、纠错码”描述构造依据。ML-KEM 属于格基密钥封装，ML-DSA 属于格基签名，SLH-DSA 属于散列基签名。三者用途不同，不能仅按“后量子”合并成同一种算法。

### 3.3 散列与可扩展输出

SHA-2、SHA-3、SM3 提供固定长度摘要；SHAKE 提供可扩展输出，Keccak 是相关置换构造。散列和 XOF 也会作为其他算法的构件，但有散列积木不代表已实现所有依赖散列的完整协议或签名方案。

### 3.4 消息认证与完整性

HMAC、CMAC 和 EIA3 用于消息完整性/认证。EIA3 基于 ZUC，属于消息完整性算法，不是加密算法。各项已登记的向量和参数范围以[演示目录](../../demos/README.md)为准。

### 3.5 密钥派生与口令散列

HKDF、PBKDF2 用于派生密钥；Argon2 用于口令散列。它们不是加密算法，也不能互相替代。具体输入限制、参数和测试向量见[覆盖矩阵](../standards/COVERAGE.md)。

### 3.6 随机数生成与平台测评

HMAC-DRBG 和 SM3-HMAC-DRBG 是确定性随机比特生成构造。平台测评时，用户提交 Python 生成器与参数；后端在隔离 sandbox 中执行生成器，再由服务端测评流程对生成样本运行登记的统计检测并生成报告。前端用于编辑和用户侧试验，以及提交任务、查看报告；不会依据浏览器生成的样本给出平台测评结论。

统计检测针对给定样本和配置，不证明随机源的熵、抗攻击能力或密码模块合规性。测试项与判定边界见[随机数标准覆盖](../standards/COVERAGE.md)及项目的随机性测评说明。

### 3.7 数学、采样与编码原语

有限域、多项式、矩阵、NTT、采样、位/字节转换和编码是多种算法共享的构件，尤其常见于格基和纠错码算法。它们帮助表达算法步骤，但单独的数学构件不等于完整 ML-KEM、ML-DSA、SLH-DSA 或 McEliece 实现。块类型和连接规则见[用户指南](./USER-GUIDE.md)，端口与生成细节见积木索引及对应标准条目。

## 4. 从积木到验证与平台测评

1. **选择算法类别。** 从[积木索引](../blocks/INDEX.md)进入对应主题，先确认算法用途、输入类型和限制。
2. **搭建流程。** 在 Blockly 中连接积木；跨算法构件复用时，按端口类型和标准数据表示进行转换。
3. **生成并运行代码。** 选择 Python 或 JavaScript 生成代码，在用户侧运行环境中检查行为。代码生成供实验与学习使用，不会自动产生平台测评结论。
4. **复现演示。** 导入[演示工作区](../../demos/README.md)，并按该项登记的标准向量、性质断言或交叉验证检查；不要把固定输入结果误读为标准向量。
5. **提交随机性测评。** 如需平台统计报告，提交 Python 生成器和测评参数；后端在隔离 sandbox 中运行生成器并产生样本，再由服务端测评流程执行检测、记录参数与结果。该流程只针对随机性测评，不替代其他算法的验证。

## 5. 教学、科研与生产使用边界

| 使用目标 | 当前适合做什么 | 必须补齐的证据/能力 |
|---|---|---|
| 教学 | 用积木观察算法结构、生成代码、运行登记的演示与测试向量 | 明确区分原语、算法片段和完整算法；演示结果仅适用于其登记的输入和断言 |
| 科研 | 将平台用于受控实验、算法教学研究或实现对比的起点 | 固定源码版本、标准/向量来源、参数、随机种子或样本、依赖与硬件环境；保留原始结果、日志和重复实验。现有记录尚未覆盖所有算法的统一复现清单 |
| 生产 | 可用作设计参考或原型，不得直接把 Blockly 生成代码或平台统计报告当成生产安全结论 | 需要目标标准的完整测试、威胁模型、密钥与熵管理、侧信道/实现安全评估和独立验证。当前平台没有 NIST CAVP/ACVP 或 CMVP/FIPS 140-3 认证，也不对熵源作认证 |

后端随机性统计检测属于样本诊断层。NIST SP 800-22 不能替代 SP 800-90A/B/C 对 DRBG、熵源及完整随机比特生成器的适用评估；算法向量测试也不能替代密码模块验证。具体范围和路线见[标准覆盖矩阵](../standards/COVERAGE.md)及项目中的开发/评测说明。

## 6. 范围说明

- 积木可用、代码可生成、演示通过和标准原文齐全，是四种不同状态。
- 演示只覆盖其登记的输入、参数、向量或性质；需要了解未覆盖项时查[标准覆盖矩阵](../standards/COVERAGE.md)。
- 平台随机性统计报告不是 CAVP/ACVTS 算法验证结果或 CMVP/FIPS 140-3 密码模块验证/认证，也不是熵源质量证明。
- 本页所称后量子密码不包括量子密钥分发等量子通信技术。
