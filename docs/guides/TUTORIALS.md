# 用户教程：从编辑器到可验证算法

本组教程面向 CipherCat 用户，逐步介绍编辑器操作；后端测评步骤会单独说明如何转到 Metacrypto 平台。每个步骤按“操作、界面状态、预期结果、排错”组织。

截图用于说明共享编辑器的界面操作；源构建版本未逐张记录，因此不作为当前部署版本的页面证据。截图不替代标准公式、伪代码或官方测试向量。

## 1. 第一个五分钟：打开编辑器并导入 Demo

目标：打开 Blockly 编辑器，导入一个已有工作区，并确认块链已被正确加载。

### 步骤 1：进入编辑器

- **操作**：在 CipherCat 项目列表点击“新建项目”。
- **界面状态**：项目列表显示“文档”“EN”和“新建项目”；编辑器显示工具箱、工作区和代码面板。
- **✅ 预期**：中央区域显示 Blockly 工作区，右侧显示代码面板。
- **⚠️ 排错**：页面为空时刷新页面并确认前端服务可访问；仅显示工具箱时检查浏览器控制台和 Blockly 初始化日志。

![项目列表与新建项目入口（CipherCat 界面示例）](/docs-assets/tutorials/01-project-list.png)

![空白编辑器（CipherCat 界面示例）](/docs-assets/tutorials/02-editor-empty.png)

_图 1：CipherCat 项目入口与空白编辑器示例，不代表 Metacrypto 的首页或项目入口。_

### 步骤 2：导入工作区

- **操作**：打开“更多 → 导入工作区”，选择 `demos/AES-Atomic-Round.json`。
- **界面状态**：工作区顶层显示四个 AES 原语块；它们没有值接口连线。
- **✅ 预期**：四个原语块已导入并显示在工作区；此时代码面板仍为空白占位，需在步骤 4 点击“生成”后查看代码。
- **⚠️ 排错**：导入失败时确认选择的是 Blockly JSON/XML 文件，而不是标准 Markdown 或源代码文件。

## 2. 从块链生成代码

目标：确认当前工作区可以生成目标语言代码，并理解生成代码与平台后端随机性测评的边界。

### 步骤 3：选择生成语言

- **操作**：在右上角语言下拉框选择 Python 或 JavaScript。
- **界面状态**：语言菜单显示目标语言，工作区内容保持不变。
- **✅ 预期**：代码面板的语言标识和后续生成结果与选择一致。
- **⚠️ 排错**：同一次验证只使用一种输出语言；固定语言后再比较结果。

![已选择 Python 的编辑器语言控件（界面示例）](/docs-assets/tutorials/04-editor-imported.png)

_图：截图显示已收起的语言控件及当前 Python 选择；截图用于定位控件，不展示展开菜单或切换后的状态。_

### 步骤 4：生成并阅读代码

- **操作**：点击“生成”。
- **界面状态**：右侧代码面板显示完整生成代码，包含输入、块链调用和返回值。
- **✅ 预期**：代码面板不再是空白占位文本；代码中的函数顺序与工作区块链一致。
- **⚠️ 排错**：代码为空时检查生成器和顶层块；类型不匹配时先看[用户指南中的数据类型与积木连接说明](./USER-GUIDE.md)。

![生成 Python 代码后的编辑器（界面示例）](/docs-assets/tutorials/05-generated-python.png)

_图 3：选择 Python 并生成后，右侧代码面板显示带语法高亮的实际代码。_

### 步骤 5：复制代码

- **操作**：点击“复制代码”，将生成代码带到用户自己的运行环境。
- **界面状态**：代码面板保留生成结果；项目工作区仍可继续编辑和重新生成。
- **✅ 预期**：粘贴到目标环境后，内容与当前所选语言的完整生成代码一致。截图只展示复制控件，不证明剪贴板操作已成功。
- **⚠️ 排错**：CipherCat 编辑器负责构建工作区和生成代码，不在浏览器中执行平台后端随机性测评；需要测评时转到 Metacrypto 的任务入口，由后端执行。

![代码面板与复制代码控件（界面示例）](/docs-assets/tutorials/05-generated-python.png)

_图：示例画面包含生成代码区域和“复制代码”控件；粘贴操作仍需在实际运行环境单独确认。_

## 3. 从算法阶段到完整函数

目标：把已验证的原子块链封装成可复用函数，再逐步增加参数和循环。

### 步骤 6：建立函数边界

- **操作**：使用 `procedures_defreturn` 创建 `SM4_Sbox` 函数，加入 `x: int` 参数，并把 S 盒查询块接到返回接口。
- **界面状态**：函数定义块、`int` 参数、S 盒查询块和返回接口同时可见。
- **✅ 预期**：函数有明确输入、输出和返回块；参数类型与所连接的块兼容。
- **⚠️ 排错**：此处的 `int` 是 S 盒索引示例，不适用于字节串、多项式或其他算法参数。

![函数定义 Demo（界面示例）](/docs-assets/tutorials/08-function-demo.png)

_图 4：函数 Demo 展示带 `int` 参数的函数定义、返回块和 `SM4_Sbox` 调用。_

### 步骤 7：生成并核对函数代码

- **操作**：点击“生成”，检查代码面板中的函数实现。
- **界面状态**：代码面板显示生成的 `sm4_sbox` 和调用它的 `sm4_sbox_lookup`；截图中的 Blockly 画布只显示函数定义块，不展示调用块。
- **✅ 预期**：生成代码包含函数实现及其辅助调用，且函数体与工作区定义相符。
- **⚠️ 排错**：若要在主流程中拖入调用块，请按[函数积木指南](./BLOCKLY-GUIDE.md)操作；本图不作为调用块画布状态的证据。

## 4. 查看平台后端随机性测评

目标：区分代码试验、向量验证和平台后端随机性测评。

> 后端测评页面需要在已登录的 `metacrypt_server` 环境中打开任务详情后截图。本仓库不嵌入登录页、401 错误页或虚构的报告截图；报告字段和判定边界以 [GM/T 0005 测评边界](../standards/gmt0005-randomness/03-Backend-Evaluation.md) 为准。

### 步骤 8：提交测评任务

- **操作**：在 Metacrypto 平台的“任务 → 随机性测试”页面，选择或提交 Blockly 算法并填写测评参数。
- **界面状态**：表单从项目预检结果读取算法类型（只读），用户确认样本位数、序列数、种子和 GPU 选项；提交后返回任务编号。
- **✅ 预期**：任务进入排队、运行或完成状态，并有可追踪的任务编号。
- **⚠️ 排错**：前端不负责生成平台测评样本，也不在浏览器中执行服务端传来的代码；平台测评由后端完成样本生成和统计检测。

### 步骤 9：阅读测评报告

- **操作**：在 `metacrypt_server` 任务列表 `/tasks/index` 打开对应任务详情 `/tasks/detail/<jobId>`，查看样本信息、检测项、参数和失败原因。
- **界面状态**：任务详情显示后端实际返回的摘要、检测明细和参数字段；规则/检测器版本字段只在报告实际提供时核对。
- **✅ 预期**：任务详情展示后端返回的摘要和检测明细；当前报告是否包含完整规则/检测器版本信息，以实际字段为准，不把缺失字段写成已追溯。
- **⚠️ 排错**：统计检测通过不等于密码算法认证；“结构已覆盖”“Demo 已验证”和“后端测评”必须分别记录。
