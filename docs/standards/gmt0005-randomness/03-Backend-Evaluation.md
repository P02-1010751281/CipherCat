## 执行面

```text
metacrypt_server Python 隔离容器
  └─ 执行用户提交的 Python 生成代码并返回样本

metacrypt_server Go 检测器
  ├─ 校验样本与检测参数
  ├─ 执行检测项目
  └─ 保存检测结果并生成报告

CipherCat 前端
  ├─ 允许用户试跑自己的代码
  └─ 展示后端报告或实验结果
```

浏览器试验结果不能替代平台后端随机性测评；前端也不应接收并执行服务端任意 `exec(user_code)`。平台执行用户提交的生成代码并检测其产出的样本，但不证明生成器诚实、熵源合格或算法获得认证。样本来源、随机种子、样本长度、失败项目和规则版本应进入报告元数据。

## 当前批次判定范围

平台默认使用 20,000 bit 长度档、1000 条样本。后端逐项统计 `P-value ≥ 0.01` 的样本数，并对 1000 个 `Q-value` 做 10 分箱均匀性检验（`αT = 0.0001`）；只有两层条件都满足且检测套件覆盖该长度档的适用项目，报告才给出“通过”。样本数不足、报告行数不匹配或检测项目不完整时，结论为“无法判定”，不把单条样本通过当作批次通过。

标准定义 15 种检测方法；按各长度档参数和检测模式展开后，报告应包含完整且有序的 22/27/30 个 P/Q 参数化项目（分别对应 20,000、1,000,000、100,000,000 bit）。检测方法数不等于报告项目数；缺项、重复、乱序或 P/Q 配对不一致均不能形成批次判定。

## NIST SP 800-22 检测组合（`nist`）

除默认的 GM/T 组合外，后端另有 NIST SP 800-22 Rev.1a 组合，由检测器 `-suite nist` 选择、任务参数 `testSuite` 指定。两者是并列的两套检测项清单，判定口径（样本通过率 + 样本均匀性）相同，但列结构、项目名和参数不同，报告不能互相套用。

NIST 组合含 15 项检测、16 个报告项目（序列检测同时报告两个 P 值），参数按参考实现 `sts/src/assess.c` 的默认值取：块内频数 M=128、非重叠模板匹配 m=9/N=8、重叠模板匹配 m=9/M=1032、通用统计 L=7、线型复杂度 M=500、序列 m=16、近似熵 m=10、矩阵秩 M=Q=32。其中 4 项是 GM/T 组合没有的：非重叠模板匹配（§2.7）、重叠模板匹配（§2.8 全 1 模板）、随机偏移（§2.14）、随机偏移变量（§2.15）。GM/T 组合的“重叠子序列检测”在数学上就是 NIST 的序列检测（§2.11），两套组合各自保留自己的项目名。

验收方式是与 NIST STS 参考实现交叉核对：用参考实现 `sts/src/*.c`（含 cephes igamc）与后端检测器跑同一份 e 常数前 1,000,000 bit 数据，逐项比对 P 值。15 项中 14 项逐位一致；线型复杂度一项相差 1.4×10⁻⁴，原因是参考实现把 π₀ 写成 0.01047，而 SP 800-22 §2.10.4 正文与 GM/T 0005-2021 都印 π₀ = 0.010417，本实现按标准正文取值。矩阵秩与块内最大 1 游程两项按各自标准的概率表实现（NIST 用 §2.4.4 表与公式计算的 P₃₂/P₃₁，GM/T 用 T 表值），因此两套组合在这两项上数值不同，属预期差异而非缺陷。

复现该交叉核对的方法：取 NIST STS 源码（`sts/src/` 与 `sts/include/`）、写一个 main 依次调用 `Frequency`、`BlockFrequency(128,n)`、`CumulativeSums`、`Runs`、`LongestRunOfOnes`、`Rank`、`DiscreteFourierTransform`、`NonOverlappingTemplateMatchings(9,n)`、`OverlappingTemplateMatchings(9,n)`、`Universal`、`ApproximateEntropy(10,n)`、`LinearComplexity(500,n)`、`Serial(16,n)`、`RandomExcursions`、`RandomExcursionsVariant`，把 `stats[]/results[]` 都指向 stderr，输入取 `randomness/data/data_e` 的前 1,000,000 bit；另一侧运行 `rddetector -suite nist` 于同一样本并逐项比对。仓库内不复制 NIST 的 C 源码，只保留本页记录的数值与差异说明。

多子检验项在平台报告里投影成一个 P 值：非重叠模板匹配取 148 个模板、随机偏移取 8 个状态、随机偏移变量取 18 个状态中的最差 P 值（任一子检验不过即该项不过，与 NIST 逐项判定一致）。这意味着在 α=0.01 下单条样本的该项偏严格，批量结论仍由多样本的通过率与均匀性决定。随机偏移两项要求环数 J ≥ max(0.005√n, 500)，不满足时报告为“未执行”而不是通过。

当前边界：NIST 组合只开放 1,000,000 bit 档（随机偏移检测本身要求 n ≥ 10⁶）；尚未做 1000 条样本的完整批次实测，因此该组合的报告在样本数不足时同样只给“无法判定”。这些检测不构成 NIST 认可、CAVP 验证或任何认证结论。

`Q-value` 十分箱检验仅在完整 1000 条样本时计算。格式不完整或包含非有限/越界 P/Q 值的检测器报告会被拒绝，不会将坏值当作普通未通过样本吸收进统计。

后端将单任务总测评输入限制为 100,000,000 bit，因此 1,000,000 bit 档最多生成 100 条，100,000,000 bit 档最多生成 1 条；这两档当前只提供统计诊断，不能形成 GM/T 0005 批次结论。sandbox 的 64 MiB 样本载荷限制是独立上限，并非上述档位数量的约束来源。任务状态“已完成”表示计算流程结束，不等于随机性通过。以上是当前产品实现范围，不代表通过标准认证。

当前任务结果含 `projectCodeHash`、`sampleHash` 和检测结果；任务表另存 `input_hash`，对比接口将其作为 `inputHash1/2` 返回。检测器/规则版本、报告签名与完整性仍有缺项。

| 字段 | 计算范围 | 相同值能说明什么 | 不能据此推出 |
|---|---|---|---|
| `projectCodeHash` | 提交的 Python 源码 UTF-8 字节的 SHA-256 | 两次提交的源码字节相同 | 运行环境、依赖、执行路径或报告未被篡改 |
| `sampleHash` | 按顺序送入检测器的样本字节；摘要包含样本数和每段长度 | 两批送检字节序列相同 | 熵源质量、生成器诚实或统计结果可复现 |
| `input_hash` / 对比接口的 `inputHash1/2` | 规范化 JSON 中的 `seed_hex`、`n_bits`、`m_seq`、`primitive` 参数 | 这组参数一致（`inputHashScope=parameters_only`） | 代码、样本、环境或结果相同 |
| 对比接口的 `resultsMatch` | 统计报告字段；范围标记为 `statistical_report_fields_only` | 被比较的统计字段一致 | 样本或输入相同、任务可复现、报告真实或算法正确 |

这些字段是作用范围明确的 SHA-256 指纹，不是签名、来源证明或独立复现证据。完整复现还需要保存/取得实际样本、后端与检测器版本、规则版本、执行环境、原始结果和具备完整性保护的报告。

## 尚未完成

- 检测器二进制身份、规则版本和签名/完整性保护；
- 数据库建任务与 broker 发布尚无 transactional outbox；两者之间发生进程崩溃时，待处理任务会在 90 分钟后以明确错误关闭，随后需重新提交或运维处置。Celery 迟确认、worker 丢失重投递、数据库条件认领及超时孤儿清理已实现，但属于至少一次投递下的恢复机制，不提供 exactly-once 保证；
- 端到端负例、报告签名/完整性和权限隔离测试；
- 与标准逐项条款、平台评分或论文结果的独立证据链接；
- 浏览器登录态下的完整任务提交、报告查看和对比流程验收。

因此当前项目只能描述为已实现部分平台后端测评流程，不能描述为已完成 GM/T 0005 产品测评或认证。
