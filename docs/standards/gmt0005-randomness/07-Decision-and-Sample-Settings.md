## 标准定义

标准不是“单个样本过了就通过”。每个检测项目分别对样本通过率和 `Q-value` 分布均匀性判定，
只有所有项目的两层判定同时满足，样本集才通过随机性检测。

## 公式或伪代码

```text
sample_count s = 1000
alpha  = 0.01
alphaT = 0.0001
bins k = 10

for each detection item:
    pass_count = count(P_value >= alpha)
    pass_rate_ok = pass_count >= s*(1-alpha-3*sqrt(alpha*(1-alpha)/s))

    Fi = count(Q_value in [(i-1)/k, i/k)), i=1..k
    V  = sum((Fi - s/k)^2/(s/k), i=1..k)
    PT = igamc((k-1)/2, V/2)
    uniformity_ok = PT >= alphaT

final_ok = every item satisfies pass_rate_ok and uniformity_ok
```

附录 A 的样本长度及参数配置：

| 样本长度 | 重点配置 |
|---:|---|
| 20,000 bit | `m=1000`（块内频数）、`m=4,8`（扑克）、`m=3,5`（重叠）、`m=128`（最大游程） |
| 1,000,000 bit | 增加矩阵秩；线性复杂度 `m=500,1000`；Maurer `L=7,Q=1280` |
| 100,000,000 bit | 重叠 `m=3,5,7`；推导 `k=3,7,15`；自相关 `d=1,2,8,16,32`；线性复杂度 `m=5000` |

## 项目映射

`metacrypt_server` 负责生成或接收受控样本、执行 15 项检测、计算两层判定并保存可审计报告。
CipherCat 前端只负责用户代码试跑、展示后端报告和标准解释；前端生成的样本不得直接显示可信“通过”。

## 核验与缺项

验收必须检查 1000 样本、`alpha=0.01`、`alphaT=0.0001`、10 分箱、长度档位映射、重试审计、
报告完整性和权限隔离。当前仍需把每一项后端实现与本组公式、标准附录参数及平台/论文证据逐项绑定。
